# 晴耕谷　部署前檢查清單與風險

> 還沒部署。照 CLAUDE.md 規則 8，**部署前一定先問過**。這份是到時候要逐項確認的清單。

## 一、部署會改到什麼

| 項目 | 內容 | 對既有聊天的影響 |
|---|---|---|
| Durable Object migration | `wrangler.jsonc` 新增 `v2`：`new_sqlite_classes: ["FarmRoom"]` | 只新增一個類別。`ChatServer`（v1）的資料不會被動到 |
| Worker 路由 | `src/index.js` 多了 `/farm/ws`、`/api/farmroom/*`；`/internal/*` 對外回 404 | 原有 `/api/*`、`/ws` 的處理沒有改 |
| ChatServer | 多兩個內部用的方法 `farmRoomAuth()`、`farmRoomSay()` | 沒有改資料表、沒有改既有 API |
| 前端 | `public/app.js`：一對一聊天的選單把「家族牧場」換成「我們的農場」；多了農場面板的開關 | 群組、記事本的家族牧場照舊 |
| Service Worker | `/games/farm/` 用「先連網路、連不上才用快取」 | 快取名稱沒改（`cim-static-v1`），其他檔案的策略沒變 |

## 三、部署步驟

1. `npx wrangler deploy --dry-run` 看一次設定有沒有錯。
2. `npx wrangler deploy`。migration v2 會自動套用（只會執行一次）。
3. 開聊天室確認：登入、收發訊息、傳圖、推播都正常。
4. 兩個帳號進同一個一對一聊天開農場，確認連得上、看得到對方。

## 四、風險與退路

| 風險 | 會怎樣 | 怎麼處理 |
|---|---|---|
| migration 不能倒回去 | `FarmRoom` 類別一旦建立，要移除得再寫一個 `deleted_classes` 的 migration（會刪掉所有農場資料） | 不影響聊天。若只是想先關掉遊戲，把 `app.js` 選單的入口拿掉重新部署就好，不用動 migration |
| 程式回滾 | `wrangler rollback` 可以回上一版程式，但已經套用的 migration 還在 | 舊版程式不認得 `FARM` 綁定也沒關係（沒人呼叫） |
| Service Worker 快取 | 使用者可能還拿著舊的 `app.js`，看不到「我們的農場」入口 | 重新整理一次就會更新；遊戲本身的檔案是先連網路的，不會卡舊版 |
| 免費方案用量 | 農場開著時每 10 秒一次 alarm 推進時鐘；兩人都離線就停 | 親友規模遠低於免費額度；有疑慮可在 Cloudflare 後台看 Durable Objects 用量 |
| 存檔壞掉 | 主存檔讀不出來時自動改用最近一份每日備份（壞掉的原樣留在 `farm-corrupt`）；角色或地圖區塊壞掉只影響那一筆 | 已有測試（`after-corrupt`）。最多損失當天進度 |
| 之後改存檔格式 | 舊農場缺新欄位 | 目前都用「缺就補預設值」的寫法；要改既有欄位的意義時，依 `farm.v` 寫轉換，不能清資料 |
| 拍照功能 | 照片走聊天室原本的圖片上傳，會佔聊天室的媒體空間 | 每張約 100～300 KB；有疑慮可以先拿掉 📷 鈕 |
