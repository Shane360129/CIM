# 晴耕谷：架構計畫

> Prompt 0 的產出。根據 2026-11-10 實際讀到的程式碼寫的；還沒寫任何遊戲程式。
> 「要你決定」的地方集中在最後一節，其他是我的建議做法。

## 1. 現有專案實際的樣子

| 項目 | 實際情況（檔案：位置） |
|---|---|
| 入口 | `src/index.js`：`/ws` 和 `/api/*` 全部轉給唯一一個 Durable Object `ChatServer`（`idFromName('main')`），其餘走靜態檔 `public/` |
| 安全標頭 | `src/index.js` 的 `SECURITY_HEADERS` 對所有靜態頁加 `X-Frame-Options: DENY` |
| 登入 | token 存在 `ChatServer` 的 `sessions` 資料表；前端放 `localStorage`（鍵名 `cim_token` 或 `chat_token`）；伺服器用 `userByToken()` 查、`memberOf(convId, userId)` 查是不是成員 |
| WebSocket | `ChatServer.handleWs()`，token 放在 `Sec-WebSocket-Protocol` 的 `token.xxx`；用 Hibernation API（`ctx.acceptWebSocket(server, tags)`），用 tag 分群（`u:` 聊天、`f:` 牧場、`g:` 小遊戲） |
| 三條槓 | `public/app.js` 的 `chatInfoModal()`。一對一聊天**已經是選單**（查看對方資料、置頂、背景，加上 `chatFeatureItems()` 的家族牧場、小遊戲、待辦、行事曆），不是直接開個人資料 |
| 既有的牧場 | 「家族牧場」：`src/farm.js`（規則）、`public/farm.html` + `farm.js`（畫面），資料在 `ChatServer` 的 `farm_*` 資料表（三十幾張），每個聊天室一座，群組也有；用 `window.open('/farm.html?c=…')` 開在另一個視窗 |
| CSP | `public/index.html` 的 meta：`default-src 'self'`、`script-src 'self'`、`style-src 'self'` 加 Google Fonts、`connect-src 'self'`。沒有另外寫 `frame-src`，所以同源 iframe 在 CSP 這一關是允許的 |
| Service Worker | `public/sw.js`：`.js/.css/.png/.svg/.ico/.webmanifest` 先回快取、背景更新（更新後要開第二次才看到新版）；`.json`、`.webp`、API、WebSocket 不進快取 |
| 設定 | `wrangler.jsonc`：一個 DO 綁定 `CHAT`，migration `v1` |
| 分支 | 遠端沒有 `main`。聊天室最新的程式（含家族牧場）在 `claude/cloudflare-web-chat-app-vt1qlj`；目前這個工作分支 `claude/practical-goldberg-tlvmgy` 已經把它合併進來 |

## 2. 規格和實際程式碼衝突的地方

1. **iframe 會被擋**。規格要用同源 iframe 開遊戲，但 `X-Frame-Options: DENY` 會擋掉。
   建議：只對 `/games/farm/` 底下的路徑改成 `SAMEORIGIN`，其他頁面維持 `DENY`。改 `src/index.js` 的 `fetch()` 一處。
2. **三條槓已經是選單**。規格說「目前直接開個人資料，改成先跳選單」，實際上選單已經在了。
   建議：在 `chatInfoModal()` 的一對一分支加一項「我們的農場」（備忘錄不顯示），不用改結構。
3. **已經有一款家族牧場**。見第 7 節的問題 A。
4. **登入驗證在 `ChatServer` 裡面**。新的 `FarmRoom` 自己查不到 token。
   建議：Worker 先向 `ChatServer` 問「這個 token 是誰、是不是這個對話的兩個成員之一」（新增一個只給內部用的方法），通過後才把請求交給 `FarmRoom`，並帶上已驗證的使用者 id。`FarmRoom` 不直接相信瀏覽器傳來的身分。
5. **系統訊息**。伺服器已經會自己發 `type: 'system'` 的訊息（家族牧場開墾時就有）。晴耕谷要在聊天室說一聲時，由 `FarmRoom` 請 `ChatServer` 代發，不用開放前端送新的訊息類型。
6. **分支名稱**。文件寫 `feature/farm-game`，但這個雲端工作階段只能推 `claude/practical-goldberg-tlvmgy`。見問題 B。

## 5. 伺服器與資料

- `FarmRoom`：每個一對一對話一個實例，`idFromName('farm:' + 對話 id)`，用自己的 SQLite，跟聊天資料完全分開。
- 資料表（草案）：`farm`（基本資料、時間、錢）、`chunks`（地圖格子，分區塊存成 JSON）、`objects`（建築、機器、動物、擺設）、`storage`（共用倉庫）、`players`（各自的角色外觀、背包、體力、技能、好感）、`events`（事件紀錄，給離線摘要用）、`backups`（每日備份，留 7 天）。
- 寫入：變更先記在記憶體，幾秒批次寫一次，不是每個動作寫一次。
- 時間：`FarmRoom` 用 alarm 推進遊戲時鐘，沒有人在線就停。
- 免費方案的用量上限（2026-11-10 查 Cloudflare 官方文件）：每天 100,000 次請求、13,000 GB-秒運算時間、
  SQLite 每天寫入 100,000 列、讀取 500 萬列。每天 UTC 0 點重算，超過那一項就會報錯。聊天室的 `ChatServer` 也算在同一個額度裡。
  - 收到的 WebSocket 訊息算不算請求、怎麼算：文件說法不一致（2024 年的公告寫 20 則算 1 次，現在的價目頁沒寫），所以照最壞的「1 則算 1 次」設計。
  - 因此走動不是每一步都送：方向一變才送，一直走時約每 0.9 秒補一次，對方照速度自己往前推。兩個人各玩 2 小時、一直在走，大約 2 萬則。
  - 寫入：格子整塊寫（一個動作幾列）、時間每 10 秒 1 列，兩個人玩 4 小時約 2,000～3,000 列。
  - 單一實例的儲存上限文件有 1 GB 和 5 GB 兩種寫法，農場資料遠小於這個數字。

## 6. 雙人同步協定（大綱，細節在階段 2 寫成 協定.md）

- 連線：`hello` → 伺服器回完整快照；斷線重連重新拿快照。
- 移動：自己畫面先動，每秒最多送 10 次位置，沒動不送；對方用插值顯示。
- 動作：送「請求」→ 伺服器檢查 → 廣播結果；不合法就回絕，前端修正。搶同一格先到先得。
- 兩邊都要一樣的東西（動物走動、居民行程、礦坑地形）：用同一個種子的確定性亂數各自算。

## 8. 要你決定的事

- **A. 家族牧場怎麼辦？** 晴耕谷和家族牧場是兩款各自獨立的遊戲。
  - 選項 1（建議）：兩款並存。一對一聊天的選單多一項「我們的農場」，家族牧場照舊。不動現有資料，風險最小。
  - 選項 2：一對一聊天只留晴耕谷，群組保留家族牧場。
  - 選項 3：晴耕谷做完後整個取代家族牧場（現有牧場的進度不會搬過去）。
- **B. 分支。** 這個雲端工作階段只能推 `claude/practical-goldberg-tlvmgy`。建議就在這個分支做；想照文件用 `feature/farm-game` 的話，要你自己在 GitHub 上開，或回家用本機的 Claude Code 做。
- **C. 上一輪的像素風圖包**（`public/farm-pack/`，換了家族牧場的房子、穀倉、樹、動物）要留著還是移掉？它只影響家族牧場。
- **D. 生圖來源。** 文件規劃用 ChatGPT，目前改用 Canva 生，額度用完了。要等 Canva 額度、升級方案，還是你用 ChatGPT 生？
- **E. 原圖要不要進 git？** 目前 repo 裡只有 200 像素的縮圖；原圖每張 1～3 MB，362 張大約幾百 MB。建議原圖不進 git，只放素材工具輸出的圖集。
