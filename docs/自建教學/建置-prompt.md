# 家族聊天室：建置 Prompt

> **這份是要貼給 AI（Claude Code）的。** 怎麼貼、什麼時候貼，請看《教學手冊》第五章。
>
> 簡單說：
> - **第一次**：貼「給 AI 的共通規則」＋「第 1 階段」
> - **之後**：每次只貼下一個階段
> - **開新對話時**：先貼一次「共通規則」，再貼要做的那個階段
>
> 每次只貼一個階段。一次全貼的結果通常是每項功能都只做一半。

## 給 AI 的共通規則

（從這一行開始複製，到「第 1 階段」之前結束）

```
你好，我要請你從零幫我做一個家族聊天室網站。我不會寫程式，
所以請你自己做技術決定，選合理的預設值，不要問我技術問題。
真的需要我決定的事（例如功能取捨），用一般人聽得懂的話問我。

我會一個階段一個階段請你做，這段是全程都要遵守的規則。

## 目標

一個部署在 Cloudflare 上、介面仿 LINE 的網頁聊天室，給我自己的家人親友用。
親友在手機上把網頁「加到主畫面」當 App 用，我在電腦上用瀏覽器開。
App 名稱叫「CHAT」。

所有介面文字用繁體中文（台灣用語）。程式碼註解也用繁體中文，
而且要寫「為什麼這樣做」，不要只是把程式碼翻譯一遍。

## 技術限制（一定要遵守）

- Cloudflare Workers + 單一 Durable Object 實例（固定用 idFromName('main')），
  用 Durable Object 內建的 SQLite 存所有資料。
  不要用 D1、KV、R2，不要用外部資料庫。
- Worker 名稱叫 chat。
- WebSocket 用 Hibernation API，沒人講話時 Durable Object 要能真的休眠。
  心跳用 setWebSocketAutoResponse('ping','pong')，讓 ping 不會把物件叫醒。
- 前端用原生 JavaScript，不要 React／Vue 或任何框架，不要打包工具。
  public/ 底下的檔案由 Cloudflare 直接供應。
- 除了「管理員設定碼」之外，不需要任何手動設定：不用建資料庫、
  不用設其他金鑰。需要的密鑰（Web Push 的 VAPID、各種簽章用的 HMAC key）
  第一次用到時自動產生，存進資料庫的 settings 表。
- 資料庫改版用 settings 表裡的 schema_version 做漸進式 migration。
  重新部署絕對不能弄丟既有資料。
- 定時任務用 Durable Object alarm，只在真的有待處理事項時才設定，不要定時輪詢。
- 目標是 Cloudflare 免費方案就能跑。

## 部署方式（很重要）

- 部署一律由 GitHub Actions 執行，不是由你執行。
  你的環境連不到 Cloudflare 的部署 API，這是正常的，不要試圖繞過。
- 絕對不要叫我把 Cloudflare token、Account ID 或管理員設定碼貼到對話裡。
  這些我會自己放進 GitHub 的 Secrets，你只需要在程式和 workflow 裡讀取它們。
- 本機測試需要的值放在 .dev.vars（加進 .gitignore），
  並提供一份 .dev.vars.example 說明格式。

## 資安規則（每一個階段都要遵守）

- 嚴格 CSP（script-src 'self'，不要有 inline script），加上
  X-Frame-Options: DENY、X-Content-Type-Options: nosniff、
  Referrer-Policy、Permissions-Policy。
- 前端顯示使用者內容一律用 textContent 或建立文字節點，
  不要用 innerHTML 拼接使用者內容。超連結要驗證 scheme，擋掉 javascript:。
- SQL 全部參數化。
- 所有權限檢查都在伺服器端做，不能只靠前端隱藏按鈕。
- 比對密碼、邀請碼、設定碼、簽章一律用 timing-safe 比較，不要用 ===。
- log 裡不可以出現訊息內容、密碼、token。

## 工作方式（每一個階段都要遵守）

1. 每個階段做完，一定要實際跑測試，回報真的跑出來的結果。
   不要說「應該可以」。測試失敗就修到通過再回報。
   - 純函式寫單元測試（npm run test:unit，不需要啟動伺服器）
   - API 測試實際打本機 wrangler dev（npm test）
   - 如果環境裡有瀏覽器，用 Playwright 開兩個瀏覽器實際操作一遍
2. 每個階段做完都要 commit，commit 訊息用繁體中文，
   寫清楚「改了什麼、為什麼」。
3. 每個階段做完都要更新 README.md。
4. 每個階段最後，用一般人看得懂的話告訴我：
   「這階段做完之後，你可以在網站上這樣試：1. … 2. … 3. …」
   我會照著這份清單在手機和電腦上實際試一遍。
5. 我說「幫我開 PR」的時候，幫我開一個 pull request 到 main 分支，
   並給我連結。
```

## 第 1 階段：骨架、帳號、聊天核心、自動部署

```
請做第 1 階段：

【專案骨架】
- wrangler.jsonc：Worker 名稱 chat、靜態檔目錄 public/、
  assets 設定 run_worker_first: true 與 not_found_handling: single-page-application、
  Durable Object 綁定與 new_sqlite_classes migration、
  compatibility_date 用目前日期附近。
- package.json：scripts 要有 dev、deploy、test、test:unit。
  package-lock.json 要 commit 進去（GitHub Actions 用 npm ci）。
- .gitignore：node_modules、.wrangler、.dev.vars。

【自動部署：.github/workflows/deploy.yml】
- 觸發條件：push 到 main，以及手動 workflow_dispatch。
- 加 concurrency，同一時間只跑一個部署。
- 第一步檢查三個 secret 是否都有設定：
  CLOUDFLARE_API_TOKEN、CLOUDFLARE_ACCOUNT_ID、ADMIN_SETUP_CODE。
  缺任何一個就直接失敗，錯誤訊息用繁體中文寫清楚缺哪個、去哪裡設定。
- 用 actions/checkout@v5、actions/setup-node@v5（Node 22）。
- npm ci → npm run test:unit（失敗就不部署）→ npx wrangler deploy
  → 用 stdin 把 ADMIN_SETUP_CODE 設成 Worker secret
  （echo "$ADMIN_SETUP_CODE" | npx wrangler secret put ADMIN_SETUP_CODE）。

【管理員設定碼：防止別人搶先註冊成管理員】
- 系統裡還沒有任何帳號時，註冊畫面要多一個欄位「管理員設定碼」，
  必須跟 Worker secret ADMIN_SETUP_CODE 一致才能註冊，
  註冊成功的這個人就是管理員。
- 如果 ADMIN_SETUP_CODE 沒有設定或是空的，一律拒絕第一次註冊，
  並顯示「管理員設定碼尚未設定，請到 GitHub Secrets 設定後重新部署」。
  （寧可註冊不了，也不能變成誰都能註冊成管理員。）
- 設定碼猜錯要跟邀請碼一樣有次數鎖定。
- 已經有帳號之後，這個欄位就不再出現，設定碼也不再有任何作用。

【帳號】
- 註冊、登入、登出。帳號 3–20 個小寫英文字母／數字／底線；
  暱稱可以用中文；密碼至少 6 個字。
- 密碼用 PBKDF2-SHA256（10 萬次迭代＋每人隨機鹽）雜湊。
- Session 是隨機 token，存伺服器端，放在 Authorization: Bearer header，
  不要用 cookie（這樣就沒有 CSRF 問題）。60 天沒用自動失效。
- 變更密碼後，其他裝置的登入全部失效。
- 邀請碼註冊：管理員設定邀請碼後，親友要輸入正確邀請碼才能註冊。
  邀請碼清空等於關閉註冊（已註冊的人不受影響）。
  新成員註冊後，自動和管理員建立一個私訊聊天室。
- 登入密碼與邀請碼都要有連續失敗鎖定，失敗次數存在資料庫
  （放在記憶體的話 Durable Object 一被回收就歸零，鎖定等於沒用）。

【聊天】
- 1 對 1 私訊與群組聊天，訊息永久保存。
- 已讀回條：私訊顯示「已讀」，群組顯示「已讀 N」。
- WebSocket 即時推播、「正在輸入…」提示。
- 我的記事本：可以跟自己聊天當備忘錄。

【成員隱私（伺服器端強制）】
- 管理員看得到所有成員。
- 一般成員只看得到：管理員、跟自己同在某個聊天室的人、
  以及自己輸入對方帳號加的好友。
- 看不到的人：搜尋不到、不能私訊、不能拉進群組。
  這條規則要套用在帳號清單、建立聊天室、邀請進群，以及成員資料的即時推播。

【介面】
- 仿 LINE：底部（手機）或左側（電腦）三個分頁「聊天」「好友」「設定」。
- 全尺寸響應式：小手機、手機、平板、桌面、超寬螢幕都要好用。
- 手機上關掉點兩下放大（touch-action: manipulation）。

【設定 → 管理員】（只有管理員看得到）
- 「邀請碼」輸入框＋儲存
- 「複製邀請訊息」：把網址、註冊步驟、邀請碼組成一段文字複製起來
- 「成員管理」：可以幫成員重設密碼、停用帳號
- 「下載聊天備份」：下載所有帳號、聊天室、訊息的 JSON 檔
```

## 第 2 階段：照片、語音、貼圖與訊息互動

```
請做第 2 階段：

【照片】
- 在瀏覽器端先壓縮成 JPEG（最長邊 1280px、約 450KB 以內）再上傳。
  GIF 保留原檔，維持動畫。點照片可以全螢幕放大。
- 照片和語音存在資料庫，但「訊息清單不能夾帶照片內容」：
  訊息只帶一個 /api/media/<訊息編號> 的網址，瀏覽器捲到才載入（loading=lazy）。
  <img> 帶不了登入 token，所以網址用 HMAC 簽章，並把「收件者是誰」綁進簽章裡，
  到期時間以「天」為單位對齊，讓瀏覽器快取得住。
  每次取用都要重新檢查授權：帳號還在、沒被停用、現在仍是該聊天室成員。
  （退出聊天室或被停用之後，手上的舊網址要立刻失效。）
  廣播新訊息時，每位收件者拿到的是簽給他自己的網址。
- 聊天室清單的最後一則訊息預覽，照片和語音只顯示「[圖片]」「[語音訊息]」，
  不要把內容一起送出來。

【語音】
- 用 MediaRecorder 錄音：點一下開始錄，畫面出現計時器，
  再按「送出」或「取消」。最長 3 分鐘。播放時顯示進度。

【貼圖】
- 內建一組表情貼圖。
- 自訂貼圖包：可以上傳照片做成貼圖，全家共用。
  自己加的貼圖可以長按刪除，管理員可以刪全部。

【訊息互動】
- 叫出訊息選單：手機長按約半秒、電腦按右鍵。選單裡有：
  表情回應（❤️👍 等）、回覆（引用原訊息）、複製（文字訊息）、
  設為公告、收回（送出後 24 小時內，只能收自己的）。
- 群組可以發起投票。
- 公告會釘在聊天室最上方。
- 訊息搜尋：只搜得到自己所屬聊天室的內容，LIKE 的 % 和 _ 要跳脫。
  點搜尋結果直接跳到那則訊息。
- 未讀分隔線、聊天室置頂、聊天室背景。

【連結預覽】
- 訊息裡的網址自動變成可點的連結。
- 伺服器在背景抓網頁的 Open Graph／Twitter Card／<title>，
  做成帶標題、摘要、縮圖的卡片。縮圖經由自家的簽章代理供應。
- 防 SSRF（很重要）：
  只允許 http/https；擋 IP 位址、擋沒有點的主機名、
  擋 .local／.internal／.lan 這類內網名稱、擋網址裡夾帶帳號密碼。
  而且要自己處理轉址、每一跳都重新檢查，最多 3 跳
  （fetch 的 redirect:'follow' 只會檢查第一個網址，
  外站可以用 302 把伺服器導去內網）。
- 網頁抓取要有逾時和大小上限。
- 預覽更新時只重畫那一則訊息，不要整個聊天室重畫
  （聊天室裡照片多的時候，整個重畫會讓所有照片閃一下）。
```

## 第 3 階段：通知與手機 App 化

```
請做第 3 階段：

【通知】設定頁加一個「通知」區塊，三個開關：
- 「桌面通知」：網頁開著時有新訊息就跳通知
- 「新訊息音效」
- 「離線推播（網頁沒開也通知）」：用 Web Push，
  VAPID 金鑰自動產生存進資料庫。
  推播做成「無內容喚醒」：伺服器不送訊息內容，通知只顯示「新訊息」。
  旁邊加說明：iPhone 要先用 Safari「加入主畫面」、從主畫面開啟後才能開。

【上班低調模式】放在通知區塊：
- 打開後分頁標題變成「線上文件」、分頁圖示換成文件樣式、
  通知只顯示「有新內容」。只影響這台裝置。
- 有未讀時，一般模式的分頁標題顯示「(3) CHAT」。

【PWA】
- manifest 與 App 圖示（用程式產生 PNG，不要依賴外部圖檔）。
- service worker：靜態檔用 stale-while-revalidate 快取；
  API 和 service worker 自己不進快取；換版本時清掉舊快取。
- 適當時機提示使用者「加入主畫面」，可以關掉不再提示。
```

## 第 4 階段：外觀

```
請做第 4 階段：設定頁加一個「外觀」區塊：

- 「主題」：至少十種配色（例如海洋、抹茶、經典綠、櫻花、墨白、
  復古、藍染、手札、薰衣草、夕陽），點一下立刻套用。
- 「字型」：多種字型，包含繁體手寫風格。
  字型只在選用時才下載；選擇器的預覽只抓預覽文字用到的那幾個字。
  如果要自己放字型檔，要用 unicode-range 切片，
  讓瀏覽器只下載畫面上真的出現過的字。字型授權要寫進 README。
- 「字體大小」：四段，最大那段要讓長輩看得很舒服。
- 「深色模式」：自動（跟著系統）或手動。
- 這些設定只影響這台裝置。
```

## 第 6 階段：資安總檢查

```
請做第 6 階段：用攻擊者的角度檢查整個網站。

寫一支 scripts/test-security.mjs（npm run test:security），
實際對本機 wrangler dev 發動攻擊，至少涵蓋：

- 沒登入、假 token、空 token、超長 token 存取每一個 API
- 跨聊天室越權：讀、發言、標已讀、按表情、收回、設公告、改設定、把自己加進去
- 非管理員：讀管理員設定、改邀請碼、下載備份、刪帳號、重設別人密碼
- XSS 字串、javascript: 連結、SQL injection 字串
- 搜尋範圍與 LIKE 萬用字元
- 上傳假圖片、超大 payload、超長訊息、不支援的訊息類型
- 照片網址：沒簽章、竄改簽章、改成別人的 id、改長到期日、過期、
  訊息收回後、退出聊天室後
- 連結預覽：直接指向內網，以及「外站 302 轉址到內網」
- 管理員設定碼：沒設定時第一次註冊要被拒絕、猜錯要被鎖
- 登入與邀請碼暴力破解鎖定，而且重啟伺服器後鎖定仍然有效
- 改密碼後其他裝置失效、停用帳號後立刻失效

找到任何問題就修好，然後告訴我：
測了幾項、通過幾項、找到什麼問題、怎麼修的。
```

## 第 7 階段：給家人的使用手冊

```
請做第 7 階段：寫一份給家人看的使用手冊 docs/使用手冊.md。

讀者是完全不懂電腦的人，包含長輩。要求：
- 照「你實際做出來的畫面」寫：按鈕名稱、位置、操作方式，
  每一條都要回頭對照程式碼確認，不要憑印象寫。
  例如：語音是點一下開始還是按住？電腦上叫出選單是左鍵還是右鍵？
- 涵蓋：第一次註冊（含邀請碼）、iPhone 和 Android 分開說明怎麼加入主畫面、
  聊天基本操作、照片語音貼圖、訊息選單、群組、待辦與行事曆、
  通知設定、低調模式、外觀與字體放大、記事本、帳號密碼、常見問題。
- 有一節誠實說明隱私：誰看得到誰、
  聊天內容沒有端對端加密、管理員可以匯出全部記錄。
- 最後加一節「給管理員」：邀請碼、成員管理、備份。
- 用短句、表格、步驟編號，不要用技術名詞。

寫完後檢查目錄裡的連結都能正確跳轉。
```
