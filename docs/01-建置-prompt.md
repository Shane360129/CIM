# 建置 Prompt（精簡版：不含小遊戲與今天吃什麼）

> **用途**：把這份貼給 Claude Code（或其他能寫程式的 AI 助理），從零做出一個
> 與 CHAT 核心功能相同的家族聊天室。
>
> **建議做法**：不要一次全貼。照「第 N 階段」逐段貼，每段做完、測過、commit
> 之後再貼下一段。一次全貼的結果通常是每項功能都做一半。

---

## 背景與目標

幫我做一個部署在 Cloudflare 上、介面仿 LINE 的網頁聊天室，給自己家人親友用。

使用情境是：我上班不能用手機、只能開瀏覽器，親友在手機上把網頁「加到主畫面」
當 App 用，這樣我在公司也能跟家人聯絡。

所有介面文字都用 **繁體中文（台灣用語）**。程式碼註解也用繁體中文，
而且註解要寫「**為什麼**這樣做」，不要只是把程式碼在做什麼翻譯一遍。

## 技術限制（請嚴格遵守）

- Cloudflare Workers + **單一 Durable Object 實例**（固定用 `idFromName('main')`），
  用 Durable Object 內建的 SQLite 存所有資料。
  **不要**用 D1、KV、R2，**不要**外部資料庫。
- WebSocket 走 **Hibernation API**，沒人講話時 Durable Object 要能真的休眠（省免費額度）。
  心跳用 `setWebSocketAutoResponse('ping','pong')`，讓 ping 不會把物件叫醒。
- 前端用**原生 JavaScript**，不要 React／Vue／任何框架，**不要打包工具**。
  `public/` 底下的檔案由 Cloudflare 直接供應。
- 部署要能**零設定**：不需要建資料庫、不需要手動設定任何金鑰或環境變數，
  `npx wrangler deploy` 一行就完成。需要的密鑰（Web Push 的 VAPID、圖片簽章用的
  HMAC key）在第一次用到時自動產生並存進 settings 表。
- 資料庫改版用 settings 表裡的 `schema_version` 做漸進式 migration，
  **重新部署不能弄丟既有資料**。
- 定時任務用 Durable Object alarm，而且只在真的有待處理事項時才設定，
  不要每分鐘輪詢。
- 目標是 Cloudflare 免費方案就能跑。

## 第 1 階段：帳號與聊天核心

- 註冊／登入。密碼用 **PBKDF2-SHA256**（10 萬次迭代 + 每人隨機鹽）雜湊儲存，
  比對用 timing-safe 比較（不要用 `===`）。
- Session 是隨機 token，存在伺服器端，放在 `Authorization: Bearer` header
  —— **不要用 cookie**，這樣結構上就沒有 CSRF 問題。
  60 天未使用自動失效；改密碼要讓其他裝置的登入全部失效。
- **邀請碼註冊**：第一位註冊的人自動成為管理員；之後要有管理員設定的邀請碼才能註冊。
  邀請碼清空就等於關閉註冊（已註冊的人不受影響）。
  ⚠️ 註冊第一位管理員之前的空窗期要想辦法關掉（例如要求一組預先設定的認領碼），
  否則誰先找到網址誰就是管理員。
- 1 對 1 私訊與群組聊天，訊息永久保存。
- **已讀回條**：跟 LINE 一樣顯示「已讀」，群組顯示「已讀 N」。
- WebSocket 即時推播、「正在輸入…」提示。
- **成員隱私規則（重要，必須在伺服器端強制，不能只靠前端隱藏）**：
  管理員看得到所有人；一般成員只看得到管理員、跟自己同在某個聊天室的人、
  以及自己主動輸入帳號加的好友。沒被拉在一起的親友彼此完全看不到對方的帳號，
  不能搜尋、不能私訊、不能建群。這條規則要套用在帳號清單 API、建立聊天室、
  邀請進群，以及成員資料的即時推播上。

## 第 2 階段：豐富訊息

- 圖片：在**瀏覽器端先壓縮**成 JPEG（最長邊 1280px、約 450KB 以內）再上傳。
  GIF 保留原檔以維持動畫。
- 語音訊息（MediaRecorder 錄音，顯示長度與播放進度）。
- 貼圖，以及**自訂貼圖包**（可以把家人照片做成貼圖）。
- 表情回應（對訊息按 ❤️👍）、回覆引用、投票、群組公告置頂、訊息搜尋。
- 收回訊息（送出後 24 小時內）。
- **連結預覽卡片**：訊息裡的網址自動變成超連結，伺服器在背景抓 Open Graph／
  Twitter Card／`<title>`，做成帶標題、摘要、縮圖的卡片。
  縮圖要經由自家的簽章代理供應（這樣 CSP 可以維持只允許同源圖片，
  外站也看不到親友的 IP）。
- 未讀分隔線、聊天室置頂、聊天室背景、我的記事本（跟自己聊天當備忘錄）。

## 第 3 階段：離線推播與 PWA

- Web Push 離線通知，VAPID 金鑰**自動產生**存進 settings，零設定。
- 推播做成「**無內容喚醒**」：伺服器不送訊息內容，通知只顯示中性文字。
  （上班偷看的時候比較低調，也避免內容經過推播服務。）
- PWA：manifest + service worker，手機瀏覽器「加入主畫面」後像原生 App。
- service worker 對靜態檔做 stale-while-revalidate 快取；
  API 與 service worker 自己不進快取。

## 第 4 階段：外觀

- 多種風格主題（至少十種，例如海洋、抹茶、櫻花、墨白、復古、藍染、薰衣草、夕陽…）。
- 多種字型可選，含繁體與日系手寫字型。字型**只在選用時才下載**；
  選擇器裡的預覽只抓預覽字串用到的幾十個字。自架字型要用 `unicode-range` 切片，
  讓瀏覽器只抓畫面上真的出現過的字所在的那幾片。
- 深色模式（自動／手動）、四段字體大小（長輩友善）。
- **上班低調模式**：分頁標題顯示成「線上文件」、分頁圖示換成文件樣式、
  通知只顯示「有新內容」。只影響這台裝置。
- 全尺寸響應式：小手機／手機／平板／桌面／超寬螢幕。
- 手機上要關掉「點兩下放大」（`touch-action: manipulation`）。

## 第 5 階段：聊天室共用小工具

打開任何聊天室，右上角 ☰ 的「聊天室功能」區塊要有：

- **✅ 待辦清單**：全家共用，誰加的、誰完成的都看得到。
- **📅 行事曆**：生日、聚餐、繳費提醒，到時間所有成員都收到通知
  （含離線推播給沒開網頁的人）。

## 第 6 階段：資訊安全

- 嚴格 CSP（`script-src 'self'`，不要有 inline script），
  加上 `X-Frame-Options: DENY`、`nosniff`、`Referrer-Policy`、`Permissions-Policy`。
- 前端渲染訊息一律用 `textContent` 或建立文字節點，
  **不要用 `innerHTML` 拼接使用者內容**；超連結要驗證 scheme（擋 `javascript:`）。
- SQL 全部參數化。搜尋要跳脫 LIKE 的 `%` 和 `_`，
  而且只能搜到自己所屬聊天室的內容。
- 登入與邀請碼嘗試都要有次數鎖定，**失敗次數存資料庫**
  —— 放在記憶體的話 Durable Object 一被回收就歸零，鎖定等於可以繞過。
- 伺服器對外抓取（連結預覽、縮圖代理）要防 SSRF：只允許 http/https、
  擋 IP 位址、擋無點主機名、擋 `.local`／`.internal` 這類內網名稱、擋網址夾帶帳密。
  **而且要自己跟轉址、每一跳都重新檢查** —— `fetch(redirect:'follow')`
  只會檢查第一個網址，外站可以用 302 把伺服器導去內網。
- 圖片與語音**不要夾在訊息清單裡送出來**：訊息只帶一個簽章網址，
  瀏覽器捲到才載入。`<img>` 帶不了登入權杖，所以用 HMAC 簽章並把收件者綁進網址，
  到期時間以「天」對齊讓瀏覽器快取得住；**授權每次重新檢查**
  （帳號還在、沒被停用、現在仍是該聊天室成員），
  所以退出聊天室或被停用之後舊網址要立刻失效。
- log 不可以寫入訊息內容或密碼。

## 驗收方式（每一輪都要做，不要只說「應該可以」）

1. 純函式寫**單元測試**，不需要啟動伺服器。
2. 寫 **API 煙霧測試**，實際打本機 `wrangler dev`，驗證權限、隱私規則、核心流程。
3. 寫**攻擊者視角的資安測試**：實際嘗試未登入存取、偽造 token、跨聊天室越權、
   非管理員提權、XSS、SQL injection、SSRF、暴力破解鎖定、token 生命週期。
4. 用 Playwright 開**兩個瀏覽器**互相對打，驗證即時同步與 UI。
   量測實際的 bounding box／computed style，不要用肉眼判斷。
5. 效能相關的改動要**附上前後數字**，不要只說「變快了」。

每一輪改完都跑過全部測試再 commit。commit 訊息用繁體中文寫清楚
「改了什麼、為什麼這樣改、量到的數字」。
