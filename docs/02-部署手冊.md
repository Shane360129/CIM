# CHAT 部署手冊

**給完全沒寫過程式的人。** 照著做就會有一個屬於自己的家族聊天室網址。

- 需要時間：約 20–30 分鐘（只有第一次需要）
- 需要費用：**0 元**，而且不用綁信用卡
- 需要註冊的帳號：**Cloudflare**（一定要）、**GitHub**（走方法 B 時要）

## 一、先看懂這幾個名詞

看不懂這段也沒關係，但懂了之後後面會輕鬆很多。

| 名詞 | 白話解釋 |
|---|---|
| **Cloudflare** | 一家網路公司。這裡用它的免費方案來「放」你的聊天室 —— 它同時負責跑程式和存資料，所以你不用另外租主機或資料庫。 |
| **GitHub** | 放程式碼的地方，像是程式碼的雲端硬碟。它也能幫你「按一個按鈕就部署」，所以你的電腦不用裝任何東西。 |
| **Worker** | Cloudflare 上一個會跑你程式的小單位。你的聊天室就是一個 Worker，名字叫 `chat`。 |
| **Durable Object** | Worker 旁邊附的儲存空間（內含一個 SQLite 資料庫）。你的帳號、訊息、照片都存在這裡。**重新部署程式不會弄丟它。** |
| **Token（權杖）** | 「給程式用的密碼」。人用帳號密碼登入，程式用 token。特點是：可以隨時撤銷、可以設到期日、而且**只會顯示一次**，關掉視窗就看不到了。 |
| **部署（deploy）** | 把程式送上 Cloudflare、讓網址可以打開的動作。 |

## 二、註冊 Cloudflare 帳號

1. 打開 <https://dash.cloudflare.com/sign-up>
2. 填 Email 和密碼 → 註冊。**不需要信用卡。**
3. 去收信，點信裡的連結把 Email 驗證完成。
4. 登入後，從左邊選單進入 **Workers & Pages** 頁面。

> **第一次進入 Workers & Pages 時，它會請你取一個子網域名稱。**
> 這個名稱會變成你網址的一部分，取好之後就不太好改，想一下再填。
> 例如你填 `wang-family`，之後你的聊天室網址就是
> `https://chat.wang-family.workers.dev`
>
> 建議：用英文小寫＋連字號，不要太短（太短容易被別人猜到）。

做完這步，Cloudflare 就準備好了。

## 三、選一條部署的路

兩條路**選一條就好**，結果完全一樣。

| | 方法 A：自己的電腦 | 方法 B：只用瀏覽器 |
|---|---|---|
| 需要裝軟體 | 要（Node.js） | **不用** |
| 需要 GitHub 帳號 | 不用 | 要 |
| 需要處理 token | 不用 | 要 |
| 適合 | 家裡自己的電腦 | 公司電腦、不能裝軟體、或只有平板 |
| 難度 | 指令要打對 | 步驟多但都是點滑鼠 |

> 💡 **強烈建議在自己家裡的電腦做這件事**，不要用公司電腦。
> 部署只需要做一次；之後在公司只要用瀏覽器打開網址就能聊天。

## 方法 A：用自己的電腦部署

### A-1. 先裝 Node.js

1. 打開 <https://nodejs.org/>
2. 下載上面那顆綠色按鈕（LTS 版本），一路「下一步」裝完。
3. 裝完**重新開機**一次（這樣指令才找得到）。

### A-2. 打開命令列

- **Windows**：按 `開始` → 輸入 `cmd` → 開啟「命令提示字元」
- **Mac**：按 `Command + 空白鍵` → 輸入 `終端機` → 打開

會看到一個黑底或白底、可以打字的視窗。接下來的指令**一行一行貼進去，每貼一行按 Enter**。

### A-3. 四行指令

```bash
git clone https://github.com/Shane360129/CIM.git
```
（把程式碼抓到你的電腦。如果說找不到 `git`，去 <https://git-scm.com/> 裝一下再回來。）

```bash
cd CIM
```
（進到剛抓下來的資料夾。）

```bash
npm install
```
（安裝需要的工具。第一次會跑一兩分鐘，畫面會滾很多字，是正常的。）

```bash
npx wrangler login
```
（登入 Cloudflare。會自動跳出瀏覽器請你授權，按「Allow」。授權完回到命令列。）

```bash
npx wrangler deploy
```
（**部署！** 跑完會印出你的網址，像 `https://chat.你的子網域.workers.dev`。）

把那個網址記下來，然後**直接跳到 [第四節](#四-️-部署完成後立刻做這件事)**。

### Windows 使用者注意

如果在 PowerShell 執行 `npm` 或 `npx` 出現
「**因為這個系統上已停用指令碼執行**」，那是系統的 PowerShell 安全原則擋住了。
解法：改用「**命令提示字元（cmd）**」執行同樣的指令，
或把指令改成 `npm.cmd install`、`npx.cmd wrangler deploy`。

## 方法 B：只用瀏覽器部署

這條路從頭到尾只需要瀏覽器，適合不能裝軟體的電腦。

### B-1. 註冊 GitHub 帳號

1. 打開 <https://github.com/signup>
2. 填 Email、密碼、使用者名稱 → 註冊 → 去收信驗證。

### B-2. 把程式碼放進你自己的 GitHub

**如果這個 repo 已經是你自己的**（你就是 Shane360129），跳過這步。

否則：打開 <https://github.com/Shane360129/CIM> → 右上角按 **Fork** → **Create fork**。
這樣程式碼就複製到你自己的帳號底下了。後面所有「你的 repo」都指這一份。

### B-3. 拿 Cloudflare 的 Account ID

1. 登入 <https://dash.cloudflare.com/>
2. 進入 **Workers & Pages**
3. 在頁面右側找到 **Account ID**，按旁邊的複製鈕。
4. 先貼到記事本存著。

### B-4. 建立 Cloudflare API Token

1. 在 Cloudflare 右上角點你的頭像 → **My Profile**
2. 左邊選 **API Tokens** → 按 **Create Token**
3. 在範本列表裡找 **Edit Cloudflare Workers** → 按它旁邊的 **Use template**
4. 下面的設定**不用改**，直接滑到最底按 **Continue to summary**
5. 按 **Create Token**
6. ⚠️ **這一頁會顯示一串很長的英數字，這就是 token。它只顯示這一次。**
   立刻複製下來貼到記事本。關掉視窗就再也看不到，只能重新建一個。

> 💡 建議在建立時把 **TTL（有效期限）** 設成一年或更短。
> 到期後再建一個新的就好，這樣萬一哪天不小心洩漏，風險也有盡頭。

### B-5. 把兩個值存進 GitHub

1. 打開**你的** repo → 上方 **Settings**
2. 左邊選單找 **Secrets and variables** → 點 **Actions**
3. 按 **New repository secret**，新增第一個：
   - **Name**：`CLOUDFLARE_API_TOKEN`
   - **Secret**：貼上 B-4 的那串 token
   - 按 **Add secret**
4. 再按一次 **New repository secret**，新增第二個：
   - **Name**：`CLOUDFLARE_ACCOUNT_ID`
   - **Secret**：貼上 B-3 的 Account ID
   - 按 **Add secret**

> 名稱要**一字不差**（全大寫、底線），打錯就會部署失敗。
>
> 存進去之後，連你自己都看不到內容了（只能刪掉重設）。這是正常且安全的設計：
> GitHub 會加密保存、不會印在執行紀錄裡，別人 fork 你的 repo 也拿不到。

### B-6. 按下部署

1. 打開你的 repo → 上方 **Actions** 分頁
2. 左邊選 **「部署到 Cloudflare」**
3. 右邊出現 **Run workflow** 按鈕，按它

### ⚠️ B-7. 這一步最容易出錯：選對分支

按下 Run workflow 之後會跳出一個小框，裡面有一個 **Use workflow from** 的下拉選單。

**它預設選的不一定是最新的程式碼。**

這個 repo 目前的狀況是：預設分支是 `claude/bypass-corporate-chat-dg8d38`，
但最新的程式（包含所有資安修正、圖片載入優化）在
**`claude/cloudflare-web-chat-app-vt1qlj`**，比預設分支新了 30 個 commit。

所以：**把下拉選單改成 `claude/cloudflare-web-chat-app-vt1qlj`**，再按綠色的 Run workflow。

> 如果不改，部署出去的會是舊版本 —— 網站能開，但少了後來修的東西。

**一勞永逸的做法**：把這個分支合併進預設分支（開一個 Pull Request 然後 Merge），
之後預設分支就是最新的，不用每次記得改。

### B-8. 看結果

- 約一分鐘後會出現一顆綠色勾勾 ✅
- 點進那次執行 → 展開 **「部署」** 那個步驟 → 往下找，會看到你的網址，
  長得像 `https://chat.你的子網域.workers.dev`
- 如果是紅色叉叉 ❌，點進去看錯誤訊息，對照[疑難排解](#十疑難排解)

## 四、⚠️ 部署完成後立刻做這件事

**這一節請務必現在做，不要晚點再說。**

程式的設計是：**第一個註冊的人自動成為管理員**，而且在那之前，任何人打開
網址都可以註冊（因為還沒有人能設定邀請碼）。

也就是說，從部署完成到你註冊完成之間，**誰先找到你的網址，誰就是你家聊天室的
永久管理員** —— 管理員可以重設任何人的密碼、下載全部聊天記錄。

所以：

1. **馬上**打開你的網址
2. 點「**註冊**」
3. 建立你自己的帳號（帳號 3–20 個小寫英文字母／數字／底線，密碼至少 6 個字）
4. 註冊完成 → 你就是管理員 👑，別人再也不能無邀請碼註冊了

這個空窗期只有幾十秒，但這幾十秒值得你認真對待。

## 五、邀請家人加入

1. 在網頁右下（或左側）點 **設定**
2. 找到 **管理員** 區塊
3. 在輸入框填一組**邀請碼**（例如 `wang888`），按 **儲存**
4. 點 **複製邀請訊息** —— 它會把網址＋步驟＋邀請碼一起複製好
5. 把複製好的內容用 LINE 或簡訊傳給家人

家人收到後：打開網址 → 註冊 → 註冊時填入邀請碼。
註冊完系統會**自動幫他們建立一個跟你的聊天室**，一進來就找得到你。

### 想關閉註冊

把邀請碼**清空**再按儲存，就沒有人能再註冊了（已註冊的人完全不受影響）。
建議家人都進來之後就這樣做，之後要加人再臨時填一組。

## 六、之後要怎麼更新

程式有新版本時：

- **方法 A 的人**：
  ```bash
  cd CIM
  git pull
  npx wrangler deploy
  ```
- **方法 B 的人**：到 **Actions** → **部署到 Cloudflare** → **Run workflow**
  （記得再次確認分支選對了）

**更新不會弄丟任何資料。** 訊息、帳號、照片都在 Durable Object 裡，
換程式碼不會動到它。資料庫結構如果有變更，也會在第一次開啟網頁時自動完成。

## 七、備份你的聊天記錄

⚠️ **這個系統沒有自動備份。** 請偶爾手動做一次：

1. 用管理員帳號登入
2. **設定** → **管理員** → **下載聊天備份**
3. 會下載一個 `chat-backup.json` 檔，裡面是所有帳號、聊天室、訊息

建議每隔一兩個月做一次，存到你平常用的雲端硬碟。
重要的照片建議另外單獨存一份。

## 八、Token 安全守則

只有走方法 B 的人需要注意這節。那串 token 等於「可以操作你 Cloudflare 上所有
Worker 的鑰匙」，如果洩漏，對方能把你的網站換成假的釣魚頁面（掛在你自己的網址上，
看起來毫無異狀），或者部署一段程式把聊天記錄倒出來。

守則很簡單：

- ✅ **只**貼進 GitHub 的 Secrets 欄位
- ✅ 建立時設定到期日（TTL）
- ✅ 不用了就去 Cloudflare → My Profile → API Tokens 把它 **Delete**
- ❌ 不要貼進程式碼、不要貼進 README、不要貼進聊天室、不要存在共用的記事本
- ❌ 不要截圖傳給任何人

另外最重要的一件事：**你的 Cloudflare 帳號請開啟兩步驟驗證**
（My Profile → Authentication → Two-factor authentication）。
那個帳號實際上是你全家聊天記錄的鑰匙。

## 九、費用會不會爆

**不會。Cloudflare 免費方案不會給你帳單。**

機制是這樣：超過免費額度時，Cloudflare 的做法是**讓那類操作回一個錯誤**，
不是繼續跑然後寄帳單。要開始計費，你必須**主動**升級到付費方案（US$5/月）。
你沒升級就不可能被扣錢。

免費額度（每天台灣時間早上 8 點重置）：

| 項目 | 每天免費 |
|---|---|
| 請求數 | 100,000 次 |
| 資料寫入 | 100,000 列 |
| 執行時間 | 13,000 GB-s |
| 儲存空間 | 5 GB |

一家十個人以內用，一天大概幾千次請求，離上限還有一個數量級。

唯一會慢慢長大的是**儲存空間**。照片會壓到 450KB 以內，5GB 大約可以放一萬張。
幾年內不會是問題，但偶爾留意一下。

## 十、疑難排解

| 症狀 | 原因與解法 |
|---|---|
| 部署失敗，說少了 secret | 兩個 secret 的名稱要**一字不差**：`CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_ACCOUNT_ID`。常見錯誤是多了空白或拼錯。 |
| 部署成功但網站是舊的 | Run workflow 時分支選錯了。見 [B-7](#️-b-7-這一步最容易出錯選對分支)。 |
| 部署失敗，說沒有權限 | Token 建立時沒選 **Edit Cloudflare Workers** 範本，或 token 已過期／被刪除。重新建一個再更新 secret。 |
| 打開網址是 404 | 第一次進 Workers & Pages 時沒設定子網域。回 Cloudflare 的 Workers & Pages 頁面設定好，再部署一次。 |
| PowerShell 說「已停用指令碼執行」 | 改用「命令提示字元（cmd）」，或把指令改成 `npm.cmd` / `npx.cmd`。見[方法 A 最後一段](#windows-使用者注意)。 |
| 找不到 `git` 指令 | 到 <https://git-scm.com/> 裝 Git，裝完重新開機。 |
| 家人說邀請碼不對 | 邀請碼**區分大小寫**，而且前後空白會被去掉。請用「複製邀請訊息」功能，不要自己手打。 |
| 連續輸錯被鎖住 | 密碼連錯 8 次鎖 10 分鐘，邀請碼連錯 5 次鎖 15 分鐘。等時間過了就好，這是防止別人暴力破解的保護。 |
| 手機收不到通知 | iPhone 必須先用 **Safari** 加入主畫面、**從主畫面的圖示開啟**，才能開啟離線推播。見使用手冊。 |

還是卡住的話，把錯誤訊息完整複製下來再去問人 —— 錯誤訊息通常已經說了答案。
