# 生圖批次的執行方式（給負責生圖的 agent 看）

你要用 Canva 的 AI 生圖工具，把一個批次清單裡的每一張圖生出來，並留下紀錄。不要寫遊戲程式，不要 git commit，不要改清單以外的檔案。

## 工具
用 ToolSearch 載入：`select:mcp__Canva__generate-image,mcp__Canva__get-generate-image-job`

## 清單
`art-src/farm/待生成/第N批.json` 是一個陣列，每筆有 `id`、`name`、`aspect`、`bg`、`needs_doll_base`、`prompt`。

## 每一張圖的做法（一次只跑一張，做完一張再做下一張）
1. 先看 `art-src/farm/生圖紀錄.jsonl`：這個 `id` 已經有 `"status":"ok"` 的紀錄就跳過。
2. 呼叫 `mcp__Canva__generate-image`：
   - `prompt`：清單裡的 `prompt` 原文，一個字都不要改
   - `aspectRatio`：清單裡的 `aspect`
   - `imageReferences`：一律放畫風基準圖 `{"type":"MEDIA","id":"MAHahcQnoJc"}`；`needs_doll_base` 為 true 時，再加一筆 1-01 素體圖（media id 從生圖紀錄.jsonl 裡 id 為 "1-01" 的那筆拿；找不到就把這張標成 `"status":"blocked"`、note 寫「缺 1-01」，做下一張）
   - `user_intent`：`Generate game art asset <id> for the user's farm game`
3. 拿到 jobId 後一直呼叫 `mcp__Canva__get-generate-image-job` 直到 SUCCESS 或 FAILURE（PENDING 就再問，不用 sleep；Bash 的 sleep 會被擋）。
4. SUCCESS 時結果裡有：media id、一個 canva.com 連結、一張縮圖和它在本機的路徑（`[Image: source: ...png]`）。
   - 把縮圖複製到 `art-src/farm/第N批/<id>.thumb.png`
   - 把 prompt 寫到 `art-src/farm/第N批/<id>.txt`
   - 看縮圖檢查（縮圖只有 200 像素，只抓明顯的問題）：背景是不是均勻的純色（`bg` 是 null 的場景圖除外）、是不是手繪卡通風（不是像素風、不是 3D）、東西的數量和排列大致對不對、有沒有明顯的文字；建築類要「正對鏡頭、看不到側面牆」。
   - 明顯不合格：重生一次（最多重生 1 次），prompt 原文後面加一行修正，例如「背景改成完全均勻的純洋紅色 #FF00FF，不要有雜點」「物件之間再拉開，不要互相碰到」「拿掉圖上所有文字和編號」「完全不要像素風」「建築要正對鏡頭，完全看不到左右側面牆」。兩張裡留比較好的那張。
   - 在 `art-src/farm/生圖紀錄.jsonl` 加一行 JSON：`{"id","name","batch","status":"ok","media_id","link","attempts","note"}`。note 用繁體中文一句話寫這張圖的狀況（例如「符合」「只有 14 個，少了 2 個」「農舍略帶斜角」）。link 用工具回傳的那個 canva.com 連結原文。
5. FAILURE 或工具報錯：
   - HTTP 409：有別的生圖還在跑，重試（可以先做幾次別的工具呼叫再試，最多重試 8 次）
   - 內容被拒絕：加一行紀錄 `"status":"failed"`、note 寫原因，做下一張
   - 額度用完、帳號限制這類「之後每張都會失敗」的錯誤：加一行 `"status":"quota"`，立刻停下來回報

## 回報（最後的訊息）
簡短列出：成功幾張、失敗哪幾張和原因、哪幾張有瑕疵（note 不是「符合」的）、有沒有因為額度停下來。不用貼圖。
