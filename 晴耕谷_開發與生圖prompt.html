晴耕谷：雙人農場遊戲 prompt 集

給 Claude Code 的開發 prompt ＋ 給 ChatGPT 的生圖 prompt。「晴耕谷」是暫名，可以整份取代。2026-11-10 整理。每個 prompt 右上有「複製」；ChatGPT 的 prompt 複製時會自動在前面加上「共同畫風設定」。勾「做完了」會記在這台電腦的瀏覽器裡。

專案現況（讀 GitHub 得到的）

  • 分支：實際在用的程式在 claude/bypass-corporate-chat-dg8d38（main 上讀不到 package.json），還有 1 個未合併的 PR。回家先決定：合併 PR 後從 main 開分支，或直接從那個分支開 feature/farm-game。
  • 前端：純 HTML/JS，沒有框架和打包工具（public/index.html、public/app.js、public/style.css）。
  • 後端：Cloudflare Worker（src/index.js）＋ Durable Object ChatServer（src/chatserver.js），資料存在 Durable Object 內建的 SQLite。部署用 wrangler deploy 或 GitHub Actions。
  • 即時通訊：原生 WebSocket /ws（Hibernation API），伺服器用 sendToUsers() 推事件。
  • 三條槓：就是 #btn-chat-info（menu 圖示）。目前一對一聊天按下去直接開對方個人資料（chatInfoModal() → showProfile()）。現成的 openSheet()、openModal() 可以直接拿來做選單。
  • CSP（index.html 的 meta）：不能用 inline script、不能載入 CDN、HTML 裡不能寫 style=""、連線只能連自己網域。所以遊戲要放在 public/ 裡，用同源 iframe 開。
  • Service Worker（sw.js）：要確認快取不會讓遊戲更新後還在讀舊版。
  • 訊息類型白名單：伺服器只收 text/image/sticker/audio/poll，遊戲如果要發「系統訊息」到聊天室，需要改伺服器。

以上是從網頁讀到的摘要，其中幾項是讀取工具整理的，不是逐字原文。Claude Code 回家會自己再讀一次程式碼確認（Prompt 0 有要求）。

使用流程

  1. 把這個 HTML 帶回家，放進專案的 docs/farm-game/（Claude Code 之後會讀裡面的生圖批次清單）。
  2. ChatGPT 先做 第 0 批 畫風基準圖，重畫到滿意為止，之後所有圖都以它為準。生圖可以和開發同時進行。
  3. Claude Code：貼 Prompt 0 → 它讀專案、寫規格和計畫 → 你看過、回答它的問題、確認。
  4. 依序貼階段 1～9，一次一個階段。每個階段做完：照它說的方法測（兩個瀏覽器、兩個互為好友的帳號）→ 沒問題才讓它 commit。
  5. 素材：ChatGPT 的原圖下載後放到 art-src/farm/第N批/，檔名用編號（例如 1-01.png），並把當時用的 prompt 存成同名 1-01.txt，再貼 素材處理 prompt。
  6. 隔天或對話太長：開新對話貼 接續 prompt。要加內容：用 內容擴充 prompt。
  7. 要部署上線前，先讓 Claude Code 列出變更和風險，你自己確認後再部署。

【遊戲規格】
■ 基本
- 暫名「晴耕谷」（之後可改）。類型：2D 農場生活模擬（種田、畜牧、釣魚、採礦、和小鎮居民交流）。所有名稱、角色、劇情、美術都是原創，不使用任何現有遊戲的名稱、角色、地名、美術或音樂。
- 畫面：手繪卡通風，不是像素風。正面俯視 3/4 視角（看得到物件正面和一點頂部，不是斜 45 度等角）。
- 美術由我用 ChatGPT 生成「多個元素」的圖，你寫工具去背、切圖、縮放、組合。
- 介面文字全部繁體中文。
- 目標：內容量足夠玩 500 小時以上（見內容量表）。所有內容資料化（JSON），之後加內容不用改程式。

■ 入口（嵌在聊天室裡）
- 一對一聊天（conv.type 為 dm，不含只有自己的備忘錄）右上角的三條槓 #btn-chat-info，目前直接開對方個人資料。改成先跳出選單：「個人資料」「我們的農場」。群組維持原本行為。
- 每一組好友（每個 dm 對話）各自擁有一座農場，用對話 id 對應。
- 遊戲開在面板裡：桌機蓋在聊天區上（可切全螢幕），手機全螢幕。右上角有關閉鈕，關閉後回到原本的聊天。
- 遊戲放在 public/games/farm/，用同源 iframe 載入，遊戲的 CSS/JS 不影響聊天室。
- 遵守現有 CSP：不用 inline script、不用 CDN、HTML 裡不用 style 屬性（用 JS 設 el.style 或 class），連線只連自己網域。盡量不用函式庫：Canvas 2D ＋ 原生 JS ES modules。
- 維持現有做法：沒有打包工具，public/ 裡的檔案直接部署。

■ 雙人共同經營
- 兩人共用同一座農場、同一個錢包、同一個倉庫；各自有自己的角色、背包、體力、技能等級、和居民的好感度。
- 兩人同時上線：即時看到對方走動、動作、頭上的聊天泡泡和表情。
- 一人離線：另一人照常玩，進度存在伺服器；離線的人上線時看到「你不在時發生的事」摘要。
- 時間：遊戲時鐘只在至少一人在農場裡時走，一天約 15 分鐘現實時間（可調）。兩人都在線時，兩人都上床（或過了凌晨 2 點昏倒）才換日；只有一人在線時由他決定。
- 以伺服器為準：地圖格子、物品、金錢、動物、時間都由伺服器決定。角色移動在自己畫面先動，再同步給對方（平滑插值）。兩人搶同一格作物時先到先得。
- 雙人限定內容：合力搬大石頭或大樹根、雙人釣傳說魚、一起做料理有加成、節慶雙人賽、互送禮物、在農場留便條給對方。

■ 角色與紙娃娃
- 建立角色時選「男生」或「女生」，再自訂：膚色、眼睛、眉毛、嘴巴、髮型、髮色、上衣、下身（褲或裙）、鞋子、帽子、配件、名字。之後可以在家裡衣櫃換裝。
- Q 版約 2.5 頭身。男女共用同一套身體，差別在五官、髮型和預設服裝；所有服裝男女都能穿。
- 身體拆成零件：頭、軀幹、左右手臂、左右腳。
- 圖層順序（後到前）：後髮 → 後手臂（側面時）→ 身體 → 下身 → 鞋 → 上衣（洋裝類會隱藏下身）→ 前手臂 → 臉部五官 → 前髮 → 帽子 → 配件 → 手持工具。
- 方向：正面、背面、側面（另一側用鏡像）。
- 動作不畫逐格動畫，全部用程式讓零件動（位移、旋轉、上下彈跳、擠壓伸展）：待機、走路、揮工具、澆水、釣魚、吃東西、坐下、開心跳。所以一件衣服只要正、背、側三張圖。
- 髮色、膚色、衣服顏色用程式換色：可換色的圖是白到淺灰色，載入時依目標顏色上色並快取，一張圖可以變出很多顏色。
- 居民（NPC）也用同一套紙娃娃零件組成，加上自己專屬的髮型和服裝；對話時另外顯示大頭像（有多種表情）。

- 一天：早上 6 點起床到凌晨 2 點；商店有營業時間；居民有每日行程。

給 ChatGPT 的生圖 prompt

生圖工作流程

  1. 在 ChatGPT 建一個專案（Projects）叫「晴耕谷美術」，所有生圖都在裡面做。
  2. 先做 第 0 批 畫風基準圖，滿意了就下載保存。之後每開一個新對話，都先上傳基準圖，說「之後的圖都沿用這張的畫風」。
  3. 每個 prompt 開頭都要有「共同畫風設定」。這頁的複製鈕已經自動幫你加上。
  4. 紙娃娃類（五官、髮型、衣服、鞋、帽子）一定要同時上傳 1-01 素體圖，ChatGPT 才會畫成同樣大小。
  5. 一次只要一張圖。不滿意時說「保持構圖，只改 OO」，不要整段重貼。
  6. 下載原圖（PNG）放到 art-src/farm/第N批/，檔名用編號（例如 2-05.png），再把那次用的 prompt 存成同名 2-05.txt。
  7. 依開發進度一批一批做，不用一次全部生完。生圖有使用次數限制（依方案不同），一天做一批就好。

常見問題的修正說法

  • 背景不透明 → 「背景改成完全均勻的純洋紅色 #FF00FF，不要有雜點」
  • 物件黏在一起 → 「物件之間再拉開，至少留物件一半寬的空白，不要互相碰到」
  • 出現文字或標籤 → 「拿掉圖上所有文字和編號」
  • 變成像素風或 3D → 重貼共同畫風設定，加一句「完全不要像素風」
  • 大小不一 → 不用太在意，素材工具會統一縮放；只有紙娃娃零件要對齊素體
  • 紙娃娃零件畫成整個人 → 「只畫零件本身，不要畫身體和頭」
